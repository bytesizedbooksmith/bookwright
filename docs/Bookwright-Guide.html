1 · What it is ↑ top

Bookwright is a small app that runs locally on your own PC (in your web browser, with no internet required). You point it at your manuscript written in Markdown, choose a look, and it produces publish-ready files:

  • EPUB for Amazon KDP, Curios, BookFunnel (ARCs/promos), and your own website
  • Print-ready PDF for paperback & hardback (KDP / IngramSpark trim sizes)
  • Word (.docx), compiled Markdown, and a reading PDF for reuse elsewhere

Everything is generated from one set of source files and one styling system, so the live preview always matches what you export. You own the tool and your files — nothing is uploaded anywhere.

3 · Install & launch ↑ top

The easy way (Windows): double-click start.bat. The first run installs dependencies (a few minutes); after that it builds the app and opens it in your browser.

From a terminal:

npm install     # first time only
npm start       # builds the UI, starts the server, opens your browser

The app opens at http://localhost:4242. To stop it, close the terminal window (or press Ctrl+C).

4 · Interface tour ↑ top

The window has two halves:

  • Left sidebar — collapsible sections for loading your book, choosing a theme, editing details, managing front/back matter, adjusting typography, and exporting. Click any section heading to fold it away.
  • Right preview — a live, book-like view that updates as you make changes. A bar across the top lets you preview as different devices, or switch to the paginated 🖨 Print view.

6 · Folder & book.yaml ↑ top

A book folder looks like this:

my-book/
  book.yaml            ← metadata, theme, and the order of everything
  cover.png            ← your cover image
  fonts/               ← (optional) embedded fonts
  frontmatter/
    dedication.md
    epigraph.md
  chapters/
    01-the-letter.md
    02-the-garden.md
  backmatter/
    about-the-author.md

book.yaml is the control file. A full example:

title: The Clockwork Garden
subtitle: A Novel
author: Eleanor Vance
series: The Tinkerer's Trilogy
series_index: 1               # optional — leave blank (or omit) for no "Book N" line
publisher: Bramblewood Press
language: en
isbn: "978-1-7384521-0-6"     # optional — a UUID is generated if omitted
description: >
  Back-cover blurb…
copyright: |
  Copyright © 2026 Eleanor Vance. All rights reserved.
cover: cover.png
theme: decorative              # classic | modern | decorative

frontmatter:                   # "titlepage" & "copyright" are auto-generated
  - titlepage
  - copyright
  - frontmatter/dedication.md
chapters: chapters             # a folder (filename order) OR a single .md file
backmatter:
  - backmatter/about-the-author.md

The optional fonts:, styles:, and typography: blocks are covered in §11 and §12.

No book.yaml? You can just hand over a folder of chapter files. The app uses the folder name as the title and reads the files in order — you can fill in details in the app and Save details to book.yaml later.

7 · Markdown basics ↑ top

ElementHow to write it

Italic / bold*italic* · **bold**

That's all most novels need. Chapters can be one file each (in a chapters/ folder, read in filename order — so number them 01-, 02-…) or one big file split on each # heading.

8 · Front & back matter ↑ top

Open a book as a folder and the Front & back matter panel lets you build out the book without hand-editing config:

  • + Add from a template — Dedication, Epigraph, Foreword, Preface, Acknowledgments, About the Author, Also By, Newsletter, Sneak Peek, or a Custom section.
  • Each becomes a real Markdown file in your folder's frontmatter/ or backmatter/ directory.
  • Reorder with ↑ ↓ and remove with ✕ (removing just unlists it; the file stays).
  • Edit the prose in your own editor, then ↻ Reload.

The title page and copyright page are generated automatically from your Book Details (title, subtitle, author, series, publisher) — you never type them by hand. A matter file can begin with a small header to control how it appears:

---
title: Dedication      # used for the navigation table of contents
class: dedication      # styling hook
toc: false             # hide from the TOC
showTitle: false       # don't print the heading
---

9 · Embedded documents (letters, journals, texts…) ↑ top

Fiction is full of things characters read. Bookwright styles these distinctly. There are two forms.

Block — a whole document on its own

Wrap it in a fenced ::: block:

::: letter
Dear Margaret,

The garden is yours now. Wind it gently — it frightens easily.

[— C. A.]{.signature}
:::

::: journal
14th of October. The lilies will not keep time, however I wind them.
:::

::: text
**Etta:** Are you there?
**Bramble:** The kettle is warm.
:::

Inline — a few words woven into the prose

So it gets its own look instead of being mistaken for ordinary emphasis:

The book grew warm. [You'll have made a mess of it,]{.journal} said the aunt's hand.

Recognised types

letter, journal (diary), text (message / sms / chat), note, telegram, sign (inscription), verse (poem). Extras:

  • [— Name]{.signature} right-aligns a letter's sign-off.
  • Inside a text block, a **Name:** prefix labels the speaker and the bubbles alternate sides automatically (first speaker on the right).

Make them look the part: pair these with an embedded font (next section) — e.g. a handwriting font for journal — so a diary entry reads as real handwriting, even on a Kindle.

11 · Custom fonts ↑ top

By default, document styles use sensible system fonts (which e-readers may substitute). To make a journal look like real handwriting everywhere — including Kindle — embed your own font and assign it to a style in book.yaml:

fonts:
  - file: fonts/ShadowsIntoLight.ttf   # put the font file in your book folder
    family: Handwriting
styles:
  journal:
    font: Handwriting                  # diary/journal text uses it
  note:
    font: Handwriting

Embedded fonts are baked into the EPUB and inlined into the PDF, so they look the same in every format and on every device. styles entries also accept size, color, and align.

Licensing: only embed fonts you're licensed to redistribute. Open-license (OFL) fonts from Google Fonts are a safe choice. The sample bundles the OFL Shadows Into Light font.

12 · Typography ↑ top

The Typography panel (and a matching typography: block in book.yaml) overrides the theme per book:

  • Body font & Heading font — a system font, or one of your embedded fonts
  • Drop caps — on / off / theme default
  • Scene break — choose the ornament
  • Chapter title — size, case (Normal / Small caps / UPPERCASE), alignment, italic
typography:
  bodyFont: Garamond          # a system font, or a family from fonts: (embedded)
  headingFont: Handwriting
  dropcap: false
  sceneOrnament: "❦"
  chapterTitle:
    size: "1.7em"
    case: smallcaps           # normal | smallcaps | uppercase
    align: center             # left | center | right
    style: italic             # normal | italic

Changes preview live. Click Save typography to book.yaml to keep them. A font listed under fonts: renders everywhere; a plain system-font name is a suggestion e-readers may substitute.

13 · Previewing ↑ top

The bar above the preview offers:

  • Fit width / Kindle / Kobo / Phone / iPad — see how your text reflows at each screen width (with an e-ink tint for the e-readers). This is a representative approximation, not a per-device engine — every reading app lays text out a little differently, which is the whole point of reflowable EPUB.
  • 🖨 Print — paginates your book with the same engine as the print PDF and shows the actual pages: trim size, margins, running heads, page numbers, recto chapter openings. Changing options in the Print book (PDF) panel updates this view. (It runs the print engine, so it takes a few seconds to refresh.)

Editing a folder on disk? Make your changes in your editor, then click ↻ Reload to pull them in.

14 · Export ebook ↑ top

The Export (ebook) panel downloads:

ButtonFormatWhere it's for
EPUB · Amazon KDPEPUB 3KDP upload. Reader-controlled fonts, small file size.
EPUB · UniversalEPUB 3Curios, BookFunnel, your own site. Standards-clean, kept email-friendly.
Word (.docx)DOCXEditors, collaborators, other tools.
Compiled Markdown.mdOne clean file for reuse elsewhere.
Reading PDFPDFA screen/proof PDF (not print-ready trim — that's §15).

Both EPUBs include your cover, a full table of contents (the formats KDP and Kobo require), and embedded fonts. The generated title page carries your series line (e.g. “A Gadding Goose Novella”) and matches the on-screen preview, and the front matter is ordered the conventional way: Title → Copyright → Contents → Dedication → Epigraph → chapters. After an EPUB export, the app shows validation results. Files are also written to the output/ folder.

Reading PDF vs. Print book (PDF): the Reading PDF here is a quick on-screen proof — it has no trim size, running heads, or page numbers. For anything you upload to a printer, use Generate print PDF in the Print book (PDF) panel instead (its file name ends in -print-…).

Cover reminder: if your book has no cover yet, the panel warns you — EPUBs for KDP, Curios & BookFunnel need one. Add it under Book details (Replace) or drop a cover.png/.jpg in your folder. (Cover art is separate from formatting.)

15 · Print book (PDF) ↑ top

The Print book (PDF) panel produces a print-ready interior PDF from the same source and theme:

  • Trim size — 5×8, 5.25×8, 5.5×8.5, 6×9, and 8.5×11 in (Letter) — KDP / IngramSpark standards
  • Binding — paperback or hardcover (hardcover gets a wider gutter)
  • Header & footer — choose what the running head shows (Author/Title or Title/Chapter) and where the page number sits (bottom-center or top-outer)
  • Start chapters on a right-hand page — inserts blanks as needed
  • Page-count-aware gutter — the inner margin scales with the book's length to meet KDP's requirements; the panel shows a live estimate, and the exact gutter is locked in at export

The interior is laid out the way print books are:

  • A Table of Contents page (after the copyright page) listing your chapters with page numbers and dotted leaders.
  • Page numbers restart at Chapter 1 — front matter (title, copyright, contents, dedication, epigraph) and back matter carry no running head and no page number, and auto-inserted blank pages stay blank.
  • Chapter titles drop down the page, with no running head on the opening page.

Use 👁 Preview in print view to check the layout, then Generate print PDF (the downloaded file's name ends in -print-<trim>).

This produces the interior (the text block). Build the cover wrap (front–spine–back) in your print provider's cover tool — the spine width depends on the final page count and paper.

19 · Other operating systems ↑ top

This is the Windows version. Almost everything is cross-platform already (Node, Pandoc, and Chromium all run on macOS and Linux). The main Windows-specific piece is the native 📁 Choose folder… button, which uses a Windows (PowerShell) dialog — on other systems you'd paste the folder path instead, or swap in a Mac/Linux folder dialog.

The simplest way to adapt it is to open the project in an AI coding tool — OpenAI Codex or Claude Code — and ask it to "make the folder picker and any Windows-only paths work on macOS / Linux." The whole project is plain TypeScript, so this is a small change.

Until then, on macOS/Linux you can use every feature by pasting the folder path (or dragging in files) instead of the native folder button.
