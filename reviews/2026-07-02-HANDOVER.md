## Work items

### Quick wins
1. **Error taxonomy.** `server/api.ts` `wrap()` (**:79-86**) collapses every failure to a raw 400 —
   `exec.ts:21` rejects on `ENOENT` before the exit-code path, so a missing Pandoc shows as
   `Error: spawn pandoc ENOENT`. Add a tagged `AppError` (`PANDOC_MISSING`/`PANDOC_FAILED`/`CHROMIUM_LAUNCH`/
   `BAD_CONFIG`), classified in `exec.ts`/`pandoc.ts`/`render-pdf.ts`, mapped to statuses + actionable messages. **(M)**
2. **Pandoc-3.x preflight** — `pandoc.ts:9` is a bare bin name with no presence check; add a `pandoc --version`
   check in `server/index.ts` / a `/api/health` route. **(S)**
3. **Finish subtitle (~70% already built).** Model, title page, and Markdown export already work; the gaps are
   **EPUB OPF + DOCX metadata** (`buildPandocMeta`, `build-doc.ts:107`) and **per-theme `.tp-subtitle` CSS**. **(S)**
4. **Fix the theme bugs Fable found:** the **drop-cap toggle is dead on Classic/Modern** (`.dropcap` is styled
   only in the decorative theme); **print silently ignores user font-size/leading** overrides (CSS injection
   order); the Decorative float drop cap won't seat on the baseline; fixed 8.5×11 print margins are too wide
   to read. **(S–M)**

### Bigger (staged)
5. **Theming.** Custom-theme *saving* doesn't exist yet (themes are a closed 3-entry enum). Both lenses agree
   on order: **deepen the theme contract first** (per-theme title pages, chapter openers, running heads,
   drop-cap cap-metrics) → add a **genre-targeted theme or two** → then **saved custom themes** as a thin layer
   over the existing `Typography` override engine (a saved theme = a built-in CSS `base` + a `typography`
   preset, stored as JSON in a user-data dir, two new API routes, reusing `ThemePicker`/`TypographyPanel`).
   **Do not just add more knobs.** **(L, staged)**
6. **Tests** — a Vitest golden suite: unzip-and-assert EPUB OPF/spine order; print-PDF page-count/gutter/`%PDF`;
   pure-function units. **(M)**
